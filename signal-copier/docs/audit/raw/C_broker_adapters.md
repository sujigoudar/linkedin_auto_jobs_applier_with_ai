Engine facts every row depends on (verified):

- The engine never sends `Side.CLOSE` to an adapter; a CLOSE is resolved to the opposing BUY/SELL at the locally tracked quantity (`eng:2191-2206`). No "close intent" flag reaches `place_order` (signature `base:42-44`).
- `Signal.entry_order_type` / `price_low` / `price_high` / `entry_expiration` are parsed (`app/sources/webhook.py:127-132`) and exported (`app/export_events.py:238-240`) but are **never read** by `engine.py`, `risk.py` or any adapter (grep: only models/export/webhook/article_classifier reference them). Every adapter hardcodes its order type.
- Live-route gate: every non-`PaperBroker` ENTRY requires a human-recorded `release_approved` for `(account.broker, account.account_id, asset_class, "default")` (`eng:720-726`, `1745-1766`). `release_approved` requires every lower rung (`db:5224-5232`), and `account_entitled`+ requires `has_account_order_position_feedback` (`db:5233-5241`, `qual:115`, `base:193-221`). Sandbox/paper env vars do not exempt a route; only `PaperBroker` is exempt (`eng:1745`).
- Plain-account CLOSE requires either a real `get_broker_position` readback that matches, or `exclusive_writer_qualified=True` (`eng:2367-2408`). Managed-lifecycle entry requires `place_protective_stop` (`mgr:721-726`, `base:223-240`).
- Position tracking moves only on a FILLED result or a PENDING result carrying `filled_quantity` (`eng:1284-1293`, `2302-2311`); a PENDING with no id is `UNKNOWN_AMBIGUOUS` and its capital reservation is held forever (`led:138-150`, `eng:1236-1249`). PENDING orders are polled only through `get_order_status` (`rec:147-172`); the reconciler applies a FILLED status with `filled_quantity=None` as a **zero** delta (`rec:448`, `rec:482`).
- Every adapter test is transport-mocked (`tests/test_*_broker.py`; 289 mock/monkeypatch references across 20 files; zero `skipif`-gated venue tests). `docs/integrations/CATALOG.md:56-73` itself says only `paper` was ever exercised end-to-end.

On the specific claim "IBKR treats a cancel ack as cancel done": **IBKR has no `cancel_order` at all** (`ibkr.py` never overrides `base:101-105`). The ack-as-done pattern is in **ccxt** (`ccxt_broker.py:253-263`); Alpaca explicitly guards against it but introduces a different race (C-08).

## 3. Direct answers to the questions asked

- **"Limit/stop are parsed but market is sent" — verified for all 14 external adapters** (C-01). Robinhood is the only adapter that ever sends a non-market order, and it does so on its own (BUY → collared limit), not because the signal asked.
- **Can a CLOSE become a new short?** Yes on Tastytrade (`Sell to Open`, C-03), NinjaTrader (`sentiment: short`, C-04), MT5/MetaApi hedging accounts (C-04), IBKR/MT5 after an invisible bracket exit with `exclusive_writer_qualified` (C-07), and on any bracket-capable adapter when the CLOSE signal carries SL/TP (C-02). Alpaca/ccxt-perp/Tradovate/OANDA SELL-when-flat opens a short by venue semantics but is guarded by readback-or-flag for the stale-book case.
- **Optimistic FILLED?** None. OANDA/MT5/paper report synchronous FILLED only from the venue's own fill record; everything else reports PENDING. The silent problem is the opposite: FILLED confirmed later with no quantity never moves the book (C-06).
- **Cancel:** only Alpaca (`alpaca.py:260-292`), ccxt (`:253-263`) and paper implement it. Alpaca requires a terminal status but reads it too early (C-08); ccxt trusts the ack (C-09); IBKR has none.
- **Could a live route run through a stub?** No for signalstack/ninjatrader/rithmic/mt4_mt5/mt4_mt5_metaapi (feedback floor, C-10). Yes for IBKR (status is in-memory only), Tastytrade (wrong intent; OPTION), TradeStation (OPTION), Schwab/Robinhood (no sandbox, ≥400→REJECTED): all are release-approvable by a human sign-off that the write path never verifies beyond ordering and the feedback flag (`db:5224-5241`).
