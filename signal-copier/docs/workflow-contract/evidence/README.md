# Evidence Directory

This directory holds execution evidence and test results for the Signal Copier workflow contract.

## Files

- `executed_tests.json` — Output from the pytest plugin (tests/scenario_evidence.py). Records which tests executed, their outcomes, which scenarios they tagged, and code/config/data hashes. Generated automatically by pytest when run with the scenario_evidence plugin.

- `release_notes.yaml` — Manual configuration for release evidence: external blockers (e.g., "broker credentials not in CI"), financial risks, and profitability statement. Read by make_release_evidence.py.

- `mutation_report.json` — Mutation testing results (if generated by mutation harness). Records killed and surviving mutants.

- `APPLICATION_RESULTS.json` — Finite-domain test results from the generated admission and sizing test suites, if run via run_contracts.py. Records which of the 4,608 admission vectors and 4,500 sizing vectors passed.

## Generation Flow

1. **Run tests**: `pytest tests/test_*.py -q -p no:cacheprovider`
   - Writes `executed_tests.json`

2. **Build traceability**: `python build_traceability.py --executed evidence/executed_tests.json`
   - Updates `requirements_traceability.json` with executed status

3. **Generate release evidence**: `python make_release_evidence.py`
   - Reads `executed_tests.json`, `requirements_traceability.json`, `mutation_report.json`, `APPLICATION_RESULTS.json`, and `release_notes.yaml`
   - Writes `../RELEASE_EVIDENCE.md`

## Validation

Run: `python validate_evidence.py ../requirements_traceability.json --evidence-root ..`

This checks that:
- All TESTED_* scenarios have evidence_paths pointing to real files
- All required fields are present (code_hash, config_hash, executed_at, result, etc.)
- All results are PASS (until more scenarios are tested, expect INCOMPLETE status)

Until all scenarios are tested, this will report INCOMPLETE — which is the honest state.
