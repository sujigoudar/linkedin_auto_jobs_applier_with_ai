# Skill/Tool Discovery Catalog — Claude Code Efficiency Initiative

Recorded 2026-09-29. Phase 3-4 of the initiative. Built from real web research
(sources cited per entry) against `docs/agents/SKILL_BASELINE.md` (what
already exists) and `docs/agents/TOKEN_COST_AUDIT.md` (what's actually
wasteful here). **Nothing in this catalog has been installed.** Per Phase 18,
installation of any third-party code (skill, plugin, or MCP server) requires
a separate, deliberate security review of that specific artifact's actual
source before it touches this repository — this catalog identifies
candidates and classifies them; it does not clear them for install.

## Verification honesty note

This research was done via web search, not by cloning and reading every
candidate's full source. For items classified MUST/SHOULD INSTALL below,
"installation recommendation" means "worth a real Phase-18 source review
before installing," not "already vetted." I did not fabricate maintenance
status or licensing where I couldn't confirm it from search results — those
fields say "unconfirmed, verify before install" rather than a guess.

## Documented security context (read before installing anything below)

Real, cited academic findings confirm third-party Claude Code skills/plugins
are an active attack surface, not a theoretical one:
- **SKILLJECT** (arxiv.org/pdf/2602.14211) demonstrates an 80.7% average
  attack success rate for prompt injection hidden in a skill's auxiliary
  files (not just its main SKILL.md).
- **OpenSkillRisk** (arxiv.org/pdf/2607.20121) and **MalSkillBench**
  (arxiv.org/pdf/2606.07131) are both dedicated benchmarks for exactly this
  threat class, meaning it's considered significant enough for the research
  community to build standing benchmarks around.
- Anthropic's own guidance (support.claude.com/en/articles/11932705, and
  code.claude.com/docs/en/security-guidance) and third-party guidance
  (github.com/federiconeri/review-skill-safety) converge on the same
  checklist: read SKILL.md and every referenced file, check
  allowed-tools/disallowed-tools, look for inline shell execution, package
  installs, network calls, credential access paths, and any instruction that
  discourages review. Stars/downloads/official-sounding names are explicitly
  called out as NOT a substitute for this.

Given this repository is live-money-adjacent financial infrastructure, this
initiative treats that checklist as mandatory, not optional, for every
third-party install — including ones from marketplaces branded "official"
by someone other than Anthropic itself.

## Net recommendation for Phase 6+ (build-out)

Highest-value, lowest-risk next actions, in order:

1. **Build `.agent/model-routing.yaml` + a `Makefile` per app + `.claude/settings.json` hooks directly** (all repo-authored, zero third-party install risk, directly close TOKEN_COST_AUDIT.md's top findings). This is Phase 5/9/13 work this session can do right now.
2. **Evaluate Serena for a real Phase-18 source review** — it's the one external tool that maps directly onto a real, observed gap (repository intelligence / symbol-aware code search) and is plausibly worth the install-time security review, given its focus (Python/TS support, the exact languages this monorepo uses).
3. **Evaluate specific, individually-named plugins from `claude-plugins-official`** (Anthropic's own marketplace) if a concrete gap can't be closed by #1 — e.g. its `security-guidance` plugin, if its actual capability (once reviewed) adds something beyond this repo's existing bandit/gitleaks/pip-audit CI gates.
4. **Do not** bulk-install from any community aggregator (awesome-claude-code-*, tonsofskills.com) — the volume-over-vetting pattern in those repos is exactly what the cited academic research (SKILLJECT/OpenSkillRisk/MalSkillBench) flags as the real-world attack surface, and this repo's financial-infrastructure status makes that an unacceptable risk to accept in bulk.
5. **Do not** install Caveman or a similar output-compression skill for the audit/review subagent workflows — it actively works against the evidenced, file:line-cited reporting standard this session's own audit wave just demonstrated is valuable (e.g. the CSRF finding, the migration-correctness bug found today — both were only actionable because the reporting agent gave exact reproduction steps, not a compressed summary).
